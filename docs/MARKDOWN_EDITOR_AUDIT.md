# Аудит редактора описания публикации

## Как устроено сейчас

| Этап | Реализация |
|------|------------|
| **Хранение** | `posts.post_content` — plain text, Markdown как есть (без изменений) |
| **Создание / правка** | `CreatePost.jsx`, `EditPostModal.jsx` → `MarkdownTextarea` |
| **Просмотр поста** | `PostController` → `MarkdownHelper::toSafeHtml()` → `post_content_html` |
| **Предпросмотр в форме** | `POST /api/markdown/preview` — **тот же** `MarkdownHelper` |

Старые публикации не трогаются: в БД остаётся тот же текст, рендер на сервере не менялся (добавлен только тег `<hr>` для разделителя `---`).

## Проблема до доработки

Пользователь должен был знать синтаксис (`**`, `*`, `##` и т.д.). Панель была неполной (без разделителя, без диалога ссылки, без точного предпросмотра).

## Решение (без смены архитектуры хранения)

Расширен компонент **`MarkdownTextarea`** — не WYSIWYG, а **Markdown с визуальной панелью**:

- кнопки вставляют разметку в позицию курсора или вокруг выделения;
- подсказки при наведении (на десктопе);
- диалог «Вставить ссылку» (текст + URL);
- вкладка «Предпросмотр» с серверным рендером;
- адаптивная панель: на мобильных — горизонтальная прокрутка.

### Панель инструментов

| Кнопка | Действие |
|--------|----------|
| Ж | Жирный |
| К | Курсив |
| Заг | Заголовок (`# `) |
| Подзаг | Подзаголовок (`## `) |
| • | Маркированный список |
| 1. | Нумерованный список |
| „ | Цитата |
| 🔗 | Ссылка (диалог) |
| &lt;/&gt; | Код в строке |
| — | Разделитель (`---`) |

## Сравнение с готовыми редакторами

| Решение | Плюсы | Минусы | Вердикт |
|---------|-------|--------|---------|
| **EasyMDE** | Готовая панель + preview | CodeMirror, тяжелее, сложнее встроить в controlled React-форму | Не выбран |
| **MDXEditor** | WYSIWYG | Другая модель данных, риск несовместимости с CommonMark | Не подходит |
| **Toast UI Editor** | Богатый UI | Может отдавать HTML, нужна синхронизация с Markdown в БД | Избыточен |
| **Текущий MarkdownTextarea** | Тот же Markdown в БД, лёгкий бандл, полный контроль, серверный preview | Не WYSIWYG «как Word» | **Выбран** |

**Вывод:** для дипломного проекта с уже работающим CommonMark на PHP оптимально оставить хранение Markdown и улучшить UX панелью + серверным предпросмотром, а не подключать тяжёлый WYSIWYG-редактор.

## Чек-лист проверки

1. **Создание публикации** — `/create`, панель, предпросмотр, сохранение.
2. **Редактирование** — модалка правки, те же инструменты.
3. **Форматирование** — после сохранения на странице поста вид совпадает с предпросмотром.
4. **Старые посты** — открыть существующую публикацию, HTML без изменений.
5. **Новые посты** — жирный, списки, ссылка, разделитель отображаются корректно.
6. **Мобильный** — панель прокручивается горизонтально, вкладки на всю ширину.
