# Аудит мобильной версии (UX)

Дата: 2026-05-28  
Охват: главная, публикация, профиль, создание/редактирование, админ-панель.  
Ограничение: **бизнес-логика и API не меняются** — только вёрстка, компоненты UI, CSS, `aria-label`.

---

## 1. Текущая адаптивность (что уже есть)

| Механизм | Где |
|----------|-----|
| Breakpoints в `app.css` | 360, 400, 480, 600, 768, 900, 1024, 1200, 1400 px |
| Masonry-колонки | `masonryBreakpoints.js`: 6→5→4→3→**2 @768**→**1 @500** |
| Главная: фильтры | @600 — колонка, `font-size: 16px` у поля тегов (нет zoom iOS) |
| Пост: двухколоночный layout | @900 — медиа сверху, текст снизу |
| Создание поста | @600 — `ui-two-col` / `create-post-grid` → 1 колонка |
| Профиль | @600 — `profile-grid` → 1 колонка (перебивает inline `300px 1fr`) |
| Модалки | @480 — почти на всю ширину, `max-height: 85vh` |
| Markdown | @768 — горизонтальный скролл панели инструментов |
| Админка | @768 — сайдбар вниз, горизонтальные вкладки; @480 — компактный header |

**Вывод:** базовая адаптивность заложена (в т.ч. под критерии 2.4.2–2.4.3 диплома), но **мобильный UX не доведён** под современные паттерны (одна рука, иконки, плотность сетки).

## 2. Оценка по экранам

### 2.1 Главная (`HomePage`)

**Сильные стороны**
- Поиск + кнопка фильтров в одной строке (`homepage-toolbar`).
- Фильтры не `position: sticky` на мобильных — не перекрывают ленту.
- Чипы активных тегов/категорий, счётчик «Показано X из Y».

**Проблемы**

| # | Проблема | Влияние |
|---|----------|---------|
| G1 | **Две колонки Masonry с 500px до 768px** (`768: 2` в `MASONRY_BREAKPOINT_COLS`) | На многих телефонах в альбомной ориентации и «широких» (390–430 CSS px) карточки узкие: мелкий превью-контент, теги переносятся, сложнее попасть по тегу/названию |
| G2 | Длинная подпись чекбокса «Только публикации авторов, на которых я подписан» | Занимает 2–3 строки в панели фильтров, отталкивает от быстрого сканирования |
| G3 | Пагинация: текстовые кнопки «← Предыдущая» / «Следующая →» + ряд номеров страниц | На 360px переносится в 2–3 ряда, **зона большого пальца** перегружена, лишние вертикальные отступы |
| G4 | Панель фильтров `max-height: 640px` при открытии (@600) | Длинный скролл внутри блока; не bottom sheet — менее привычно для мобильных |
| G5 | Кнопка фильтров только иконка (хорошо), но нет badge «N активных» на самой иконке | Пользователь не видит активность фильтра без прокрутки к чипам |
| G6 | `homepage-feed-meta` длинная строка на узком экране | Мелкий текст по центру — ок, но можно компактнее (иконка + число) |

**Принципы UX:** неэффективное использование ширины (G1), не компактные контролы (G2–G3).

---

### 2.2 Страница публикации (`PostDetail`)

**Сильные стороны**
- Медиа на всю ширину после @900.
- Закрытие «×» в углу карточки.
- Кликабельные теги/категория.

**Проблемы**

| # | Проблема | Влияние |
|---|----------|---------|
| P1 | **`post-detail-title-row` без mobile-правил**: заголовок и блок `post-detail-actions` (до 3 кнопок с полным текстом) в одной строке | На 360–400px кнопки «Редактировать», «Удалить», «Опубликовать» сжимаются или переносятся хаотично; **не thumb-friendly** |
| P2 | Текстовые `btn-sm`, а не иконки + `aria-label` | Длинные подписи на EN/RU UX обычно заменяют на ✎ 🗑 ↑ (с подписью в tooltip/label) |
| P3 | Комментарии: однострочный `<input>`, отправка «→» с `padding: 0.25rem` | **Меньше 44×44 px** — риск промаха; длинный комментарий неудобно набирать |
| P4 | `post-comments-list` `max-height: 250px` | На высоких экранах мало контекста; на маленьких — двойной скролл (страница + список) |
| P5 | Сортировка комментариев — две полноразмерные кнопки «Новые» / «Популярные» | Нормально, но можно segmented control уже по высоте |
| P6 | Лайк/избранное — emoji + текст в `ui-inline-action` | Приемлемо; для одной руки лучше закрепить **нижнюю панель действий** (sticky) при прокрутке текста |

**Принципы UX:** слишком «десктопные» кнопки (P1–P2), мелкие touch targets (P3).

---

### 2.3 Профиль (`Profile`)

**Сильные стороны**
- Одноколоночный layout на мобильных.
- Статистика (работы / подписчики / подписки) в ряд.

**Проблемы**

| # | Проблема | Влияние |
|---|----------|---------|
| R1 | **Четыре вкладки** с длинным текстом («Моё портфолио», «Избранное», «Черновики», «На рассмотрении») — `profile-tabs` wrap | 2+ ряда кнопок одинакового веса — сложно переключать одной рукой; визуальный шум |
| R2 | Inline `gridTemplateColumns: '300px 1fr'` в JSX | Перебивается CSS только ≤600px; между 601–900px теоретически мог остаться узкий сайдбар (проверить на планшете) |
| R3 | «Подписаться» / «Отписаться» — полноширинная кнопка под статистикой | Ок по размеру; для reachability можно опустить в sticky footer только на чужом профиле |
| R4 | На карточках портфолио теги в `PostFeedMeta` — при 2-колоночной сетке профиля (если Masonry 2 col) — те же проблемы, что G1 |
| R5 | Пагинация профиля — классические `btn`, без иконографики | Аналогично главной |

### 2.4 Создание публикации (`CreatePost`)

**Сильные стороны**
- Медиа и форма друг под другом на мобильных.
- Markdown-панель с горизонтальным скроллом @768.

**Проблемы**

| # | Проблема | Влияние |
|---|----------|---------|
| C1 | **Три нижние кнопки** в `ui-action-buttons`: «Отмена», «Сохранить как черновик», «Опубликовать» с `flex: 1 1 100px` | На 360px часто **3 ряда** или сжатый нечитаемый текст; главное действие не в зоне большого пальца |
| C2 | Нет **sticky footer** для primary CTA | При длинном описании пользователь скроллит вверх для «Опубликовать» |
| C3 | Блок медиа `minHeight: 200px` / `maxHeight: 500px` | На маленьком экране отнимает первый экран; превью видео ок, но форма «ниже сгиба» |
| C4 | Радио «Опубликовать сразу» / «Запланировать» + `datetime-local` | Нативный picker — ок; подписи длинные — можно короче на `max-width: 480px` |

| A5 | Детальная карточка поста в админке — двухколоночный grid ломается @768 — ок | Медиа max-height 280px — норм |

## 3. Сводка по критериям запроса

| Критерий | Статус |
|----------|--------|
| Слишком большие кнопки | Частично: нижние блоки Create/Edit **высокие из-за переноса текста**, не из-за padding; вкладки профиля визуально «тяжёлые» |
| Неэффективное пространство | **2 колонки 500–768px**, длинные подписи фильтров/пагинации, админ-навигация внизу |
| Неудобные элементы | Панель фильтров, пагинация, действия владельца поста, отправка комментария |
| Адаптивность | Breakpoints есть; **пробелы**: title-row поста, thumb zone, иконки |
| Двухколоночная сетка | Осознанно до 500px = 1 col; **рискованный диапазон 500–768 = 2 col** |
| Иконки вместо текста | Почти нигде не используются для primary/secondary actions |
| Одна рука | Нет sticky bottom bars, FAB «Создать», compact nav |

### 9.6 Оставшиеся рекомендации (низкий приоритет)

1. **Главная — сортировка ленты:** при желании заменить `<select>` на segmented только для пары «новые/популярные», если API ограничит опции — иначе сохранить select.
2. **Lightbox на карточках ленты:** открытие без перехода на пост (сейчас клик ведёт на `/post/:id`) — отдельная фича, не ломает текущий flow.
3. **Pinch-zoom в lightbox:** сейчас кнопки ±; жесты — улучшение v2 (без новых зависимостей).
4. **Производительность:** 2 колонки на 320px увеличивает число DOM-узлов в viewport — при лагах на слабых устройствах можно поднять порог 2 col до `min-width: 360px`.
