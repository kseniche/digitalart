Введение
Творцы в цифровом мире остро нуждаются в специализированных платформах, которые выходят за рамки простого объединения. Им необходимы инструменты для полноценной демонстрации портфолио, поиска вдохновения, сотрудничества и получения качественной обратной связи от сообщества. 
Исторически цифровые площадки для творцов эволюционировали от простых галерей и форумов до сложных многофункциональных систем. Однако разрыв между потребностями растущего творческого сообщества и предлагаемым функционалом многих систем сохраняется. Рост творческого сообщества и потребность в специализированных платформах. Согласно отчёту Statista за 2024 год, количество цифровых художников и дизайнеров в мире превысило 50 миллионов человек, а ежегодный темп роста составляет около 12%. Пандемия COVID-19 и последующий переход на удалённую работу стимулировали массовый приток творческих специалистов в онлайн-пространство. По данным платформы Upwork, доля фрилансеров в креативных индустриях выросла на 34% за период 2020–2024 гг.. Существующие социальные сети и платформы зачастую носят общий характер, не адаптированы под специфические нужды творцов, перегружены рекламой или не обеспечивают необходимого уровня интерактивности. В этом контексте проектирование и разработка специализированного блога сфокусированной на запросах творческих людей, представляется актуальной и практически значимой задачей. Такая система позволит централизовать творческий процесс – от поиска идей до публикации готовых работ, их обсуждения и распространения в рамках единого цифрового пространства. По данным Grand View Research, глобальный рынок цифрового искусства в 2023 году оценивался в 12,8 млрд долларов и, по прогнозам, достигнет 28,5 млрд к 2030 году (CAGR 12,1%). При этом значительная часть транзакций и взаимодействий происходит на непрофильных площадках, что снижает эффективность творческого процесса и коммерциализации работ.
Целью дипломного проекта является разработка блога «Цифровое искусство», предназначенной для объединения творческих людей и предоставления им цифрового пространства для самовыражения, взаимодействия и поиска вдохновения.
Для достижения поставленной цели необходимо решить следующие задачи:
1.	Провести анализ предметной области для формирования требований к системе.
2.	Определить архитектуру программного продукта и выбрать средства проектирования, разработки и тестирования.
3.	Составить техническое задание на разработку в соответствии с установленными требованиями.
4.	Спроектировать базу данных и пользовательский интерфейс.
5.	Реализовать серверную и клиентскую части блога по основным разделам (регистрация и авторизация, профили, публикации, лента и лента подписок, комментарии и жалобы на комментарии, оценки, избранное, подписки, модерация публикаций и комментариев, рекомендации, уведомления по электронной почте).
6.	Реализовать валидацию данных, защиту от несанкционированного доступа и обеспечить надёжность работы приложения.
7.	Протестировать работоспособность блога (в том числе автоматизированное тестирование интерфейса).
8.	Разработать руководство пользователя для всех ролей системы.

Объект исследования – процессы создания, публикации, распространения и модерации цифрового контента в специализированных веб-платформах для творческих сообществ.

    Предмет исследования – методы и программные средства проектирования и реализации веб-приложения «Цифровое искусство» на стеке Laravel и React с REST API, ролевой моделью доступа, премодерацией публикаций и автоматической проверкой текстов.

Цель исследования – разработка специализированного блога «Цифровое искусство», обеспечивающего пользователям цифровое пространство для самовыражения и социального взаимодействия, а администраторам – инструменты модерации и управления контентом.

Методы исследования – анализ предметной области и аналогов, проектирование архитектуры клиент–серверного приложения и базы данных, объектно-ориентированная разработка на PHP (Laravel) и JavaScript (React), функциональное и модульное тестирование (PHPUnit, Laravel Dusk), экспериментальная проверка сценариев работы системы.

Таким образом, проектирование и разработка специализированного блога «Цифровое искусство», сфокусированного на запросах творческих людей, является актуальной и практически значимой задачей. 
 
1	Предпроектное исследование
1.1	Описание предметной области 
Предметной областью разработки является деятельность творческих людей (цифровых художников, иллюстраторов, дизайнеров) по публикации, распространению и обсуждению своих работ в сети Интернет, а также процессы взаимодействия между авторами и аудиторией. Для обоснования необходимости создания специализированного блога «Цифровое искусство» проведён анализ существующих платформ, которые используются творцами для демонстрации портфолио и социального взаимодействия.
Таблица 1 – Сравнительный анализ существующих платформ
Платформа	Тип	Основная аудитория	Функционал для публикации
Behance	Портфолио-платформа	Дизайнеры, иллюстраторы	Поддержка изображений, видео, проектов
DeviantArt	Галерея + соцсеть	Художники (все жанры)	Полная поддержка медиа, категории, теги
Pinterest	Визуальный поиск	Массовая аудитория	Публикация «пинов» 
Ни одна из рассмотренных платформ не сочетает в себе одновременно: удобного инструментария для публикации цифровых работ; развитой социальной составляющей; системы модерации, обеспечивающей безопасную среду. Таким образом, разработка блога «Цифровое искусство», объединяющего все перечисленные функции, является востребованной и актуальной.
Главная проблема, которую призвана решить система, – отсутствие специализированной среды, объединяющей в одном приложении функции портфолио, ленты публикаций, социального взаимодействия и администрирования. Ниже представлено описание ключевых бизнес-процессов.
Бизнес-процессы:
	Регистрация и авторизация – создание учётной записи с проверкой уникальности электронной почты и логина, обязательным принятием пользовательского соглашения и правил сообщества; вход по электронной почте и паролю с выдачей персонального токена доступа; выход с аннулированием токена; восстановление пароля через запрос на электронную почту и сброс по ссылке из письма.
	Управление профилем – просмотр и редактирование данных (имя, фамилия, логин, аватар, страна, сайт, биография, телефон, электронная почта) в разделе настроек; смена пароля; переключатель уведомлений по электронной почте; в личном профиле – портфолио, избранное, черновики, публикации на модерации (ожидающие и отклонённые), подписчики и подписки.
	Публикации – создание публикации (название, описание в формате Markdown, медиафайл изображения или видео, обязательная категория, теги), черновики, отложенная публикация; редактирование и удаление своих публикаций без замены уже загруженного медиа; отображение в ленте с учётом статуса модерации и даты публикации.
	Лента и поиск – просмотр ленты с поиском по заголовку, тексту описания и тегам, отдельным полем для поиска по тегам, фильтром по категории; для авторизованного пользователя – режим «только подписки»; сортировка по дате, названию и популярности (число лайков) с выбором направления; пагинация с выбором размера страницы 10, 25 или 50 записей (по умолчанию 12). Гость может открыть публикацию и профиль по прямой ссылке, но переход с карточек ленты без входа не выполняется – система предлагает авторизоваться.
	Социальное взаимодействие – комментарии (с предварительным принятием правил комментирования при первой отправке), жалобы на чужие комментарии, лайки публикаций и комментариев, подписки, избранное, просмотр списков подписчиков и подписок.
	Рекомендации – блок «Вам может понравиться» на странице публикации с учётом категории, тегов, просмотров, лайков и истории взаимодействия.
	Модерация публикаций – премодерация: после создания (не черновик) публикация получает статус «ожидает» или «отклонена» по результатам автоматической проверки по словарю запрещённых слов и ожидает одобрения администратора для показа в ленте; администратор может отклонить (автор исправляет) или удалить за нарушение. Модерация комментариев – автоматическая проверка текста; при нарушении комментарий не публикуется; пользователи могут подавать жалобы; при достижении порога (пять уникальных заявителей) комментарий автоматически скрывается; комментарии без жалоб через заданный срок (семь суток) автоматически помечаются как проверенные; администратор работает с вкладками «недавно опубликованные», «жалобы» и «все комментарии», подтверждает проверку, снимает необоснованные жалобы, восстанавливает видимость скрытых комментариев, окончательно удаляет нарушающие записи и пополняет словарь автомодерации. У заблокированного пользователя сохраняется просмотр ленты, но создание контента и социальные действия отклоняются с указанием причины блокировки.
	Уведомления по электронной почте (при включённой настройке у получателя) – одобрение публикации, добавление публикации в избранное, новый комментарий к публикации, удаление публикации или комментария администратором, блокировка и разблокировка учётной записи.
Объекты (сущности) и основные атрибуты:
	Пользователь (User): идентификатор, имя, фамилия, логин (username), электронная почта, телефон, хэш пароля, аватар, страна, сайт, биография, признак блокировки (is_banned), причина блокировки (ban_reason), настройка email-уведомлений, даты принятия пользовательского соглашения и правил комментирования, даты создания и обновления.
	Публикация (Post): идентификатор, название, содержание, путь к медиафайлу, тип медиа (image/video), автор, категория, теги, признак черновика, дата планируемой публикации, статус модерации (pending/approved/rejected), счётчики лайков, комментариев и просмотров, поля автомодерации, даты создания и обновления.
	Категория (Category): идентификатор, название; ведётся администратором.
	Комментарий (Comment): идентификатор, текст, автор, публикация, статус модерации, признак скрытия, дата скрытия, дата проверки администратором, поля автомодерации, даты создания и обновления; поддерживаются лайки и сортировка.
	Жалоба на комментарий (CommentReport): идентификатор, комментарий, заявитель, причина жалобы, пояснение (при выборе «другое»), дата подачи.
	Лайк публикации (Like): связь пользователя и публикации; допускается мягкое удаление.
	Лайк комментария (CommentLike): связь пользователя и комментария.
	Избранное (Favorite): связь пользователя и публикации.
	Подписка (Follower): связь подписчика и пользователя, на которого подписались.
	Администратор: роль пользователя (Admin) с расширенными правами модерации и управления категориями.
Участники и роли:
	Гость – неавторизованный пользователь: просмотр ленты и публичного контента, регистрация и вход; переход к публикации и профилю с карточек ленты недоступен без авторизации (доступны прямые ссылки на публикацию и профиль в пределах правил видимости).
	Пользователь (роль user) – создание и редактирование профиля и своих публикаций, лента с фильтром «только подписки», поиск и фильтры, комментарии (после принятия правил комментирования), жалобы на комментарии, лайки (если не заблокирован), подписки, избранное, рекомендации, уведомления по электронной почте при включённой настройке. Заблокированный пользователь может войти и просматривать контент, но не может создавать публикации и комментарии, ставить лайки, пользоваться избранным и подписками, изменять профиль.
	Администратор (роль admin) – все действия пользователя и доступ к панели администратора: пользователи (блокировка с указанием причины, разблокировка, удаление, восстановление), публикации (одобрение, отклонение, удаление за нарушение), комментарии (проверка, работа с жалобами, снятие жалоб, восстановление видимости, окончательное удаление), категории и теги, пополнение словаря автомодерации, формирование CSV-отчёта с дашборда.
Взаимосвязи сущностей:
User → Post – один ко многим. Внешний ключ user_id в posts. При каскадном удалении пользователя удаляются все его публикации.
User → Comment – один ко многим. Внешний ключ user_id в comments.
User → Like – один ко многим. Внешний ключ user_id в likes.
User → Favorite – один ко многим.
User → Follower – один ко многим (как подписчик, так и автор).
Post → Comment – один ко многим. Внешний ключ post_id в comments. Каскадное удаление комментариев при удалении публикации.
Post → Like – один ко многим.
Category → Post – один ко многим. Внешний ключ category_id в posts. При удалении категории, имеющей публикации, операция запрещена.
Post → Favorite – один ко многим.
Для всех связующих таблиц (likes, favorites, followers, comment_likes) предусмотрены уникальные составные индексы для исключения дублирования записей. Реализовано «мягкое удаление» (deleted_at) для основных сущностей, что позволяет восстанавливать данные администратором.

3	Проектирование программного продукта
3.1	Архитектура программного продукта
Для блога «Цифровое искусство» выбрана клиент-серверная архитектура с чётким разделением на фронтенд и бэкенд. Взаимодействие между компонентами построено на принципах RESTful API с обменом данными в формате JSON. Данный стиль обеспечивает масштабируемость, технологическую независимость частей и возможность создания альтернативных клиентов в будущем (например, мобильного приложения).
На серверной части (Laravel) используется шаблон Model-View-Controller (MVC):
	Model (Eloquent ORM) – описывает бизнес-сущности, связи между ними, атрибуты, а также мутаторы и аксессоры.
	View (шаблоны) – в классическом Laravel это Blade, но в нашем проекте роль View выполняет React-клиент, поэтому серверные View не используются, а контроллеры возвращают JSON.
	Controller (контроллеры) – обрабатывают HTTP-запросы, выполняют валидацию, обращаются к моделям данных и сервисам автомодерации и модерации комментариев, возвращают JSON-ответы.
На клиентской части (React) применён компонентный подход с использованием хуков и контекста:
	Компонентная архитектура – каждый элемент интерфейса реализован как переиспользуемый React-компонент.
	Управление состоянием – глобальные контексты авторизации и всплывающих уведомлений; локальное состояние форм и фильтров на уровне экранов.
	Маршрутизация – React Router DOM обеспечивает SPA-навигацию без перезагрузки страницы.
	Обмен с сервером – единый клиентский модуль запросов: поддержка cookie-сессии и персонального токена доступа, сохранённого в браузере, для авторизованных операций.
Выбранная архитектура продиктована требованиями к системе и обеспечивает следующие преимущества:
Масштабируемость обеспечивается горизонтальным масштабированием stateless-бэкенда и хранением медиа в S3-совместимом хранилище либо на локальном диске public (выбор по конфигурации .env).
Производительность достигается за счёт SPA (сервер отдаёт только JSON), асинхронных запросов, оптимизации запросов через жадную загрузку (with() в Eloquent), пагинации ленты (page, per_page) и сжатия статики через Vite; URL медиафайлов кэшируются в Laravel Cache на 3600 с с инвалидацией при изменении поста.
Безопасность реализована через хэширование паролей, аутентификацию по cookie-сессии и персональным токенам доступа, валидацию входных данных, преобразование Markdown в безопасный HTML, политику Content-Security-Policy, защиту от CSRF для запросов из веб-интерфейса, а также ограничение частоты запросов: вход – 5 в минуту, регистрация – 3 в минуту, смена пароля – 5 в минуту, создание контента – 20 в минуту, социальные действия – 60 в минуту, административные операции – 40 в минуту.
Надёжность обеспечивается обработкой ошибок через try-catch и стандартизированными JsonResponse, логированием исключений, транзакциями БД для переключения лайков и подписок, и «мягким удалением» (soft deletes) для восстановления данных.
Поддерживаемость обусловлена разделением на контроллеры API, модели Eloquent, сервис автомодерации, внедрением зависимостей (Dependency Injection) в Laravel, покрытием кода тестами (PHPUnit, Laravel Dusk) и соблюдением соглашений Laravel.
Предложенная архитектура полностью соответствует функциональным и нефункциональным требованиям, предъявляемым к блогу «Цифровое искусство».

Рисунок 1 – Диаграмма прецедентов информационной системы «цифровое искусство»
Актёры (роли):
	Гость – просмотр публичной ленты, регистрация с принятием соглашения и правил, вход, запрос ссылки для сброса пароля, просмотр публикации и профиля по прямой ссылке.

	Администратор – всё, что у пользователя, плюс панель администратора: статистика и CSV-отчёт, управление пользователями (блокировка, удаление, восстановление), публикациями (одобрение, отклонение, удаление), комментариями (проверка, жалобы, снятие жалоб, восстановление видимости, окончательное удаление), категориями и тегами, пополнение словаря автомодерации.
Прецеденты по актёрам:
	Гость: регистрация; вход; просмотр ленты; запрос восстановления пароля; просмотр публикации и профиля по адресу.
	Пользователь: выход; создание, изменение, удаление публикации; черновики и отложенная публикация; комментарий и жалоба на комментарий; лайк публикации; лайк комментария; избранное; подписка; лента подписок; настройки профиля; просмотр избранного, черновиков и публикаций на модерации; смена и восстановление пароля; рекомендации.
	Администратор: статистика и отчёт; управление пользователями; управление публикациями и комментариями; управление категориями и тегами; пополнение словаря автомодерации.
Диаграмма деятельности показывает переход управления между шагами ключевых процессов. 
1. Регистрация и авторизация: гость заполняет имя, фамилию, логин, электронную почту, пароль и подтверждение, принимает соглашение и правила. Система проверяет данные; при ошибке возвращает описание полей, при успехе создаёт учётную запись и выполняет вход. Повторный вход выполняется по электронной почте и паролю.
2. Публикация работы: авторизованный незаблокированный пользователь указывает название, описание, медиафайл, категорию, теги, режим публикации (сразу, по расписанию или черновик). Система сохраняет медиа в настроенное хранилище, проверяет текст по словарю; для публикуемой работы назначает статус «ожидает» или «отклонена»; в общей ленте отображаются только одобренные опубликованные работы с наступившей датой публикации.
3. Взаимодействие с контентом: система проверяет авторизацию, отсутствие блокировки и доступность публикации. Лайк переключается с обновлением счётчика. Комментарий допускается после принятия правил комментирования; при успешной автопроверке публикуется и учитывается в счётчике, при нарушении не отображается. Жалобы на комментарий накапливаются; при достижении порога комментарий скрывается.
4. Модерация: администратор одобряет или отклоняет публикации, удаляет нарушающие материалы, подтверждает проверку комментариев, обрабатывает жалобы, восстанавливает видимость или удаляет комментарии окончательно, блокирует пользователей с указанием причины. Заблокированному пользователю отказывается в действиях по изменению контента с пояснением причины.

Рисунок 3 – ER–модель

Таблицы спроектированы в соответствии с реляционной моделью и приведены к третьей нормальной форме (3NF):
1НФ – значения атомарны; повторяющихся групп в одном поле нет.
2НФ – у таблиц с составной уникальностью (likes, followers, favorites, comment_likes) нет зависимостей неключевых атрибутов от части ключа; у остальных – простой PK id.
3НФ – нет транзитивных зависимостей.
Денормализация (осознанная): поля like_count, comment_count, view_count в posts дублируют агрегаты для быстрого отображения ленты; фактические связи сохраняются в likes и comments.
Целостность (FK): каскадное удаление при удалении пользователя/поста; для category_id – restrict (нельзя удалить категорию с публикациями); уникальные пары в связующих таблицах исключают дубликаты лайков и избранного.
3.4	Проектирование пользовательского интерфейса программного продукта
Прототип интерфейса – упрощённое чёрно-белое представление экрана без детальной визуальной стилизации: фиксируются состав функциональных блоков, порядок действий пользователя, основные элементы управления и связи между экранами. Прототип отвечает на вопрос о том, какие операции выполняет пользователь и в какой последовательности.
Макет интерфейса – уточнённое представление того же экрана с применением выбранной типографики, цветовой схемы, отступов, визуальных состояний элементов. Макет отвечает на вопрос о том, как интерфейс воспринимается визуально и при практической работе.
Клиентская часть приложения построена как одностраничное приложение на React с клиентской маршрутизацией. Основные экраны: главная лента, страница публикации, профиль участника, создание работы, настройки профиля, панель администратора, страницы восстановления пароля, пользовательского соглашения и правил сообщества.

6	Руководство пользователя программного продукта
6.1	Установка и запуск приложения
В рамках дипломного проекта подготовлена пользовательская документация, обеспечивающая установку, настройку и запуск информационной системы, а также использование функционала для всех ролей. 
Процедура установки начинается с клонирования репозитория проекта и перехода в директорию приложения. Затем необходимо скопировать файл конфигурации окружения командой `cp .env.example .env` и настроить переменные окружения, указав параметры подключения к базе данных, учётные данные S3-хранилища (ключ доступа, секретный ключ, регион, имя бакета, endpoint) и URL фронтенд-приложения.
Установка зависимостей выполняется последовательно: сначала серверные зависимости командой `composer install`, затем клиентские через `npm install`. После этого необходимо сгенерировать ключ приложения командой `php artisan key:generate`, выполнить миграции базы данных и заполнение тестовыми данными через `php artisan migrate --seed`. Для компиляции фронтенд-ресурсов используется команда `npm run build` для продакшн-сборки или `npm run dev` для режима разработки с горячей перезагрузкой.
Запуск приложения осуществляется командой `php artisan serve`, которая запускает встроенный сервер разработки на адресе `http://localhost:8000`. Для продакшн-развёртывания рекомендуется настроить виртуальный хост Apache или Nginx с указанием корневой директории на папку `public` проекта.

Рисунок 46 – Страница создания публикации
Профиль открывается из меню или по имени автора. Отображаются аватар, имя, счётчики подписчиков и подписок (для авторизованных – просмотр списков), биография, страна, сайт. На чужом профиле – кнопка подписки. На своём – вкладки «Моё портфолио», «Избранное», «Черновики», «На рассмотрении» (подвкладки ожидающих и отклонённых; для отклонённых показывается причина). При блокировке на своём профиле видны метка и текст причины (Рисунок 47).
   
Рисунок 47 – Профиль пользователя
Настройки (меню аватара): имя, фамилия, логин, электронная почта, телефон, страна, сайт, биография, загрузка аватара, переключатель уведомлений по электронной почте, смена пароля. Сохранение – «Сохранить изменения»; результат отображается всплывающим уведомлением (Рисунок 48).
 
Рисунок 48 – Страница редактирования данных профиля
Выход – пункт «Выйти» в меню аватара. Восстановление пароля: со страницы входа – «Забыли пароль?», ввод электронной почты, переход по ссылке из письма и задание нового пароля.
Заблокированный пользователь может просматривать ленту и публикации; при попытке создать публикацию, комментарий, поставить лайк, изменить избранное, подписаться или сохранить настройки система сообщает о блокировке и показывает причину.

Доступ к административной панели имеют только пользователи с ролью администратора. При отсутствии прав попытка открыть панель перенаправляет на главную страницу.

Вход выполняется так же, как у обычного пользователя. После авторизации в меню аватара появляется пункт перехода в админ-панель. В верхней части панели – кнопки «← Назад» (возврат на главную без выхода) и «Выйти» (с подтверждением). Слева – вкладки: «Дашборд», «Пользователи», «Публикации», «Комментарии», «Категории | Теги». На экране панели стандартная шапка сайта скрыта (Рисунок 49–50).

Рисунок 49 – Админ-панель
Рисунок 50 – Интерфейс админ-панели

1. Вкладка «Дашборд»
Сводная статистика: пользователи (всего, активные, удалённые), публикации (всего, активные, удалённые), комментарии (всего, активные, удалённые). Кнопка «Обновить» перезагружает показатели. Кнопка «Отчёт» открывает выбор периода (неделя, месяц, квартал, год, всё время) и скачивание CSV-файла со сводкой и таблицами по пользователям, публикациям и комментариям (кодировка UTF-8 с BOM, разделитель «;»). Отдельного раздела «Отчёты» в меню нет.

2. Вкладка «Пользователи»
Компактная строка статистики (активные, заблокированные, удалённые, всего, удалено за 30 дней). Фильтр: активные или удалённые; поиск по имени, электронной почте и логину. На карточке – аватар, контакты, роли, дата регистрации, при блокировке – причина, число публикаций и подписчиков. Для обычных пользователей: просмотр деталей и публикаций; блокировка (причина обязательна, от 3 до 1000 символов); разблокировка; мягкое удаление и восстановление. Учётные записи других администраторов заблокировать или удалить нельзя.

3. Вкладка «Публикации»
Статистика: на модерации, одобренные, отклонённые, всего, удалено за 30 дней. Фильтры: на модерации, одобренные, отклонённые, удалённые, все; поиск по заголовку и тексту. На карточке – автор, даты, признак черновика или отложенной публикации, превью медиа (в детальном просмотре – ограниченный размер), текст, теги, категория, счётчики, результаты автомодерации. Действия: просмотр с комментариями к публикации; одобрить (автор получает уведомление по электронной почте при включённой настройке); отклонить с необязательной причиной (автор может исправить и отправить снова); удалить за нарушение с указанием причины. Восстановление удалённой публикации через интерфейс не предусмотрено.

4. Вкладка «Комментарии»
Статистика: на проверке, с жалобами, скрытые, всего, удалено за 30 дней. Вкладки списка: «Недавно опубликованные» (подтверждение проверки администратором), «Жалобы» (причины и данные заявителей), «Все комментарии» (фильтры: все, на модерации, проверенные, скрытые, с жалобами, удалённые). Поиск по тексту; ссылка «Открыть публикацию». Действия: подтвердить проверку; отклонить жалобы (комментарий остаётся, при автоматическом скрытии по жалобам видимость восстанавливается); снова показать скрытый комментарий; удалить окончательно; удалить с добавлением слов в словарь автомодерации. Блок «Словарь запрещённых слов» – только добавление новых слов (просмотр и удаление списка в интерфейсе не реализованы). Комментарии, не прошедшие автопроверку при создании, в ленте не отображаются; одобрение таких комментариев через панель не предусмотрено – они создаются заново автором после исправления текста.

5. Вкладка «Категории | Теги»
Категории: список с числом публикаций; создание; переименование; удаление только если к категории не привязаны публикации.
Теги: список с количеством использований; удаление тега из всех публикаций, где он встречается.

Уведомления по электронной почте (при включённой настройке у получателя): одобрение публикации, удаление публикации или комментария администратором, блокировка и разблокировка учётной записи.

3 Назначение системы
3.1 Общее описание
Блог «Цифровое искусство» предназначен для размещения работ, просмотра ленты, комментирования и взаимодействия между пользователями. Описание публикаций на стороне клиента и сервера хранится как текст; при просмотре публикации текст преобразуется в безопасный HTML средствами Markdown.
Для пользователя с ролью user система обеспечивает: регистрацию с принятием пользовательского соглашения и правил сообщества, вход по e-mail и паролю, выход с удалением текущего токена, переключатель уведомлений на e-mail, смену и восстановление пароля; создание публикации с загрузкой файла, заголовком, описанием, категорией, тегами; при публикации (не черновик) – автоматическую проверку текста: при успехе – ожидание одобрения администратора, при нарушении – отклонение; просмотр в профиле вкладок «На рассмотрении» (ожидающие и отклонённые) с причиной отклонения; просмотр ленты только для одобренных публикаций; поиск по заголовку, тексту и тегам, отдельный поиск по тегам, фильтр по категории, режим «только подписки», сортировку с направлением и пагинацию с выбором размера страницы 10, 25 или 50 записей; просмотр публикации с подсчётом просмотров, лайком, избранным, комментариями (после принятия правил комментирования) с сортировкой «новые» или «популярные», лайком комментария и жалобой на чужой комментарий; блок рекомендаций; подписку и отписку; избранное; редактирование публикации без замены медиа; у владельца профиля – вкладки портфолио, избранного, черновиков и публикаций на модерации.
Для администратора с ролью admin система обеспечивает доступ к панели администратора: дашборд со счётчиками и выгрузку отчёта в формате CSV за выбранный период; список и детальный просмотр пользователей с фильтром и поиском; блокировку и разблокировку; мягкое удаление и восстановление пользователя; список публикаций, одобрение, отклонение и удаление за нарушение; модерацию комментариев (вкладки недавних, жалоб и общего списка, подтверждение проверки, снятие жалоб, восстановление видимости, окончательное удаление); пополнение словаря запрещённых слов; управление категориями и тегами.
4 Требования к системе
4.1 Функциональные требования
Для пользователя:
1. Регистрация и аутентификация
1.1. Регистрация с полями имя, фамилия, уникальный username, уникальный e-mail, пароль и подтверждение пароля; обязательное принятие пользовательского соглашения и правил сообщества.
1.2. Вход по e-mail и паролю с выдачей персонального токена доступа (Sanctum).
1.3. Выход с аннулированием текущего токена.
1.4. Смена пароля с проверкой текущего пароля.
1.5. Восстановление пароля по электронной почте через отдельные страницы запроса и сброса.
2. Раздел «Лента публикаций»
2.1. Отображение одобренных публикаций авторов.
2.2. Поиск по заголовку, тексту описания и тегам; отдельное поле поиска по тегам.
2.2.1. Для авторизованного пользователя – режим «только подписки».
2.3. Фильтрация по категории.
2.4. Сортировка: с направлением.
2.5. Отображение в интерфейсе выбранных поля и направления сортировки.
2.6. Переход к просмотру публикации и профиля автора с карточек ленты (для авторизованного пользователя); для гостя – предложение войти (прямые ссылки на публикацию и профиль доступны).
3.Просмотр публикации
3.1. Отображение медиа, заголовка, описания, категории, тегов, даты, автора, счётчиков лайков и комментариев.
3.2. Лайк и снятие лайка с публикации.
3.3. Добавление и снятие публикации из избранного.
3.4. Просмотр комментариев с сортировкой по дате или по числу лайков; лайк комментария.
3.5. Добавление комментария после принятия правил комментирования; жалоба на чужой комментарий.
3.6. Блок рекомендаций «Вам может понравиться».
3.7. Редактирование своей публикации без замены медиафайла.
4. Раздел «Профиль»
4.1. Просмотр полей профиля.
4.2. Просмотр числа подписчиков и подписок.
4.3. Подписка и отписка на пользователя.
4.4. Для своего профиля: вкладки «Моё портфолио», «Избранное», «Черновики», «На рассмотрении» (ожидающие и отклонённые с указанием причины при наличии).
4.5. Редактирование профиля и загрузка аватара, смена пароля на экране настроек.
5.Создание и редактирование публикации
5.1. Загрузка медиафайла; ввод заголовка и описания; выбор категории; ввод тегов.
5.2. Сохранение черновика.
5.3. Указание будущей даты публикации для отложенного.
5.4. Редактирование своей публикации (текст, категория, теги, черновик, отложенная публикация) без замены медиа; удаление своей публикации с безвозвратным удалением медиа в хранилище и связанных лайков и комментариев.
6.Ограничения для заблокированных пользователей
6.1. Заблокированный пользователь может просматривать ленту и публикации, но не может создавать публикации и комментарии, ставить лайки, пользоваться избранным и подписками, обновлять профиль; при попытке действия отображается причина блокировки.
Для администратора:
Администратор пользуется тем же публичным функционалом просмотра, что и пользователь, и дополнительно:
1.	Раздел «Дашборд» – просмотр статистики по пользователям, публикациям и комментариям; формирование и скачивание CSV-отчёта за выбранный период (отдельного раздела «Отчёты» в меню нет).
2.	Раздел «Пользователи» – список со сводной статистикой, фильтр активных / удалённых, поиск; карточка пользователя; блокировка и разблокировка; мягкое удаление и восстановление.
3.	Раздел «Публикации» – список со статистикой, фильтры, детальный просмотр; одобрение, отклонение, удаление за нарушение (восстановление удалённых публикаций в интерфейсе не предусмотрено).
4.	Раздел «Комментарии» – вкладки «Недавно опубликованные», «Жалобы», «Все комментарии»; подтверждение проверки; снятие жалоб; восстановление видимости скрытых комментариев; окончательное удаление; пополнение словаря автомодерации (только добавление слов в интерфейсе).
5.	Раздел «Категории | Теги» – категории: просмотр, создание, изменение и удаление (если нет привязанных публикаций); теги: просмотр и удаление из всех публикаций.
4.2 Технические требования
	Валидация вводимых данных на клиенте в формах.
	– Повторная строгая валидация на сервере средствами Laravel Request / Validator для всех входных данных API.
	– Защита от SQL-инъекций за счёт использования Eloquent ORM и параметризованных запросов.
4.3 Эксплуатационные требования
	Среда функционирования: современные браузеры (Яндекс Браузер, Chrome, Firefox, Edge, Safari).
	– Адаптивная вёрстка под мобильные экраны.
	– Наличие инструкции по установке, настройке окружения и запуску.
4.4 Требования к информационной безопасности
1.	Аутентификация и авторизация: доступ к защищённым операциям после проверки учётных данных; для SPA с общим доменом –связка cookie-сессии Sanctum и заголовка X-XSRF-TOKEN для stateful-запросов; для API –токены Sanctum. Пароли хранятся в виде хэша (в проекте используется механизм хэширования Laravel на базе bcrypt с настраиваемым числом раундов BCRYPT_ROUNDS). Разграничение прав по ролям (user / admin) через Spatie Laravel Permission и middleware.
2.	Защита от распространённых уязвимостей: снижение риска XSS за счёт экранирования и политики Content-Security-Policy (middleware CSP); защита от CSRF для маршрутов, проходящих через веб-стек с валидацией CSRF-токена; проверка прав на каждом защищённом ресурсе на сервере; ограничение частоты запросов (throttle) для входа, регистрации, смены пароля, создания контента, социальных действий и админ-операций.

Приложение Б. Код модели Post
(фрагмент app/Models/Post.php)
<?php
namespace App\Models;

use Illuminate\Database\Eloquent\Builder;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\SoftDeletes;
use Illuminate\Support\Facades\Cache;
use Illuminate\Support\Facades\Storage;

class Post extends Model
{
    use SoftDeletes;

    protected $fillable = [
        'post_title', 'post_content', 'media_path', 'tags', 'user_id',
        'media_type', 'category_id', 'is_draft', 'published_at',
        'moderation_status', 'like_count', 'comment_count', 'view_count',
    ];

    protected $casts = [
        'tags' => 'array',
        'is_draft' => 'boolean',
        'published_at' => 'datetime',
    ];

    public function scopePubliclyVisible(Builder $query): Builder
    {
        return $query
            ->where('is_draft', false)
            ->where('moderation_status', 'approved')
            ->where(function ($q) {
                $q->whereNull('published_at')
                  ->orWhere('published_at', '<=', now());
            });
    }

    public function getImageUrlAttribute(): ?string
    {
        if (empty($this->media_path)) {
            return '/images/digital-art-1.jpg';
        }
        return Cache::remember("post_image_url_{$this->id}", 3600, function () {
            if (Storage::disk('public')->exists($this->media_path)) {
                return Storage::disk('public')->url($this->media_path);
            }
            return $this->media_path; // S3/public URL по конфигурации
        });
    }
}
